## 1. What is added

The v0.2.0 package contained training-grade chunkwise forward/backward Pallas
kernels only. v0.3.0 adds an inference layer on the same math:

### 1.1 `atomic_gdn2/inference.py::decode_step`
Single-token Pallas kernel for serving. Per batch row: state decay
`S ← Diag(exp(min(g,0)))·S`, erase term `(b⊙k)·S`, write `k·v_newᵀ`, output
`o = Sᵀ(scale·q)` — exactly the recurrence of
`atomic_gdn2/reference/ref.py::token_serial_ref` (the package's ground-truth
serial reference; no BLR shortcut is used). Serving options:
- `reset=` — per-row incoming-state zeroing (vLLM-style preemption / document
  boundaries); applied in the wrapper so the kernel keeps a TPU-legal block
  scheme;
- `state_dtype=jnp.bfloat16` — bfloat16 state storage with float32 compute
  (halves state bytes; a single rounding on the returned state);
- `stability_tau=` — optional Frobenius-norm cap on the returned state
  (inference-only safety; the training path is never capped);
- `fuse_prologue=True` — q/k l2-normalization and gate squashing computed
  inside the kernel from raw projections, so activations never materialize in
  HBM (prologue-fusion method; see §3.1 for the source of this method).

### 1.2 `atomic_gdn2/inference.py::chunk_forward_inference`
Forward-only prefill with bounded outputs: reuses the v0.2.0 training kernels
(scores, WY ladder solve) and a slim variant of the fused C+D kernel that
materializes only `(o, h_final)` — no `h_pre_all`/`v_new_all`/`gc_last`
training residuals. Segment segmentation with state carry across Pallas
launches is inherited unchanged from the v0.2.0 pipeline
(`max_chunks_per_call`). Serving options: `segment_ids` and `cu_seqlens`
(document resets at chunk granularity — a chunk spanning two documents must be
split by the caller), `state_dtype`, `stability_tau`.

### 1.3 Tests — `tests/test_inference_v03.py`
Ten gates, all executed in JAX Pallas interpret mode (CPU-exact emulation of
the kernel bodies) and all passing: decode-vs-serial (bit-tight, atol 1e-4),
reset-vs-separate-runs, chunked-prefill-vs-serial (contract tolerance),
segment-ids-vs-separate, bf16-state drift (measured 0.0015 relative),
stability-tau cap, fuse-prologue-vs-pre-activated equivalence,
cu-seqlens-vs-segment-ids, multi-segment prefill (state carry across Pallas
launches bit-identical to a single-call run; serial equivalence within the
documented chunked contract), three-document decode with resets.

### 1.4 TPU validation — `attestation/v03-inference-tpu/`
Live Colab TPU v5e-1 run (jax 0.11.2, notebook
`notebooks/gdn2_v03_tpu_eval.ipynb`, commit `904d5f9`): **all 11 gates PASS**
(7 interpret semantics gates + compiled decode-vs-serial + compiled
prefill-vs-serial + backward smoke + perf). Compiled prefill has 3 boundary
outliers out of 16384 elements (0.018%) — the documented chunked-vs-serial
contract tail (TPU `Precision.HIGHEST` lowers to bf16×3 dot passes; `wy_eps`
damping accumulates at state-carry positions); tolerance 0.15 with an
in-file comment. Recorded throughput: prefill ≈1650–1750 tok/s, decode
≈29 tok/s per step (≈136 ms/step) — dominated by per-call Pallas dispatch in a
Python loop; the kernel math itself is ~10⁵ FLOPs/step. Both numbers are
fp32 + `HIGHEST`-path figures; a bf16 compute config is future work.
Evidence: `attestation/v03-inference-tpu/{REPORT,gates,run1_gates_A,
run1_gates_B,perf_inference,env_manifest}.json`.

### 1.5 Two root-cause fixes found and documented during validation
1. **TPU Mosaic block-shape legality**: a Pallas TPU block's last two dims
   must divide (8, 128) or equal the array's dims. Per-head vector blocks
   `(1,1,D)` and a `(B,)` scalar reset block are illegal → decode switched to
   `grid=(B,)` with blocks spanning the full `(H,·)` extent (legal for any
   H, D); reset moved to the wrapper; segment ids passed as a full-array block.
   (Diagnosed from the Colab error text; the rule is stated verbatim by
   JAX Pallas at compile time.)
2. **Decode output indexing**: the output line
   `o = Σ_d (scale·q)[·]·h[d,v]` initially broadcast `q` over the value
   channel (`[..., None, :]`) instead of the key axis (`[..., None]`) — a
   classical einsum-vs-broadcast slip. The state was always correct; only `o`
   was scrambled, and a uniform-`q` probe masks the bug. Caught by the new
   test suite, fixed, and the state-vs-output asymmetry documented here
   because it is a reusable lesson for block-kernel authors.

## 2. Provenance of the GDN-2 math

- **Architecture**: "Gated DeltaNet-2: Decoupling Erase and Write in Linear
  Attention", NVIDIA, arXiv:2605.22791 (May 2026). Channel-wise erase gate `b`
  (key axis) and write gate `w` (value axis); recurrence
  `S_t = (I − k_t(b_t⊙k_t)ᵀ)Diag(exp(g_t))S_{t−1} + k_t(w_t⊙v_t)ᵀ`.
- **Ground-truth recurrence used by every v0.3.0 test**:
  `atomic_gdn2/reference/ref.py::token_serial_ref` — written by the author
  (A. Omirbay) for the v0.2.0 package; it shares no BLR formula with the
  kernels and served as the oracle in the v0.2.0 attestation (145 PASS/1 OOM).
- **Pretrained reference point**: the 1.3B/95B-token GDN-2 checkpoint released
  with the GDN-2 model card (`LLM-OS-Models2/gdn2-1.3b-paper-matched`),
  converted bit-exactly to HF naming (`Akseleu/gdn2-1.3b-hf`; conversion
  evidence in `gdn2-vllm-pr/colab-v03-results-*/` and the `gdn2-hf-convert-*`
  Kaggle kernels). The inference kernels were not validated against this
  checkpoint end-to-end yet — validation is vs the serial reference.

## 3. Sources — complete and honest list

### 3.1 External methods that shaped the design (adapted, not copied)
- **maelie-labs/deltanet-tpu** v0.3.0 (Apache-2.0,
  github.com/maelie-labs/deltanet-tpu, release 2026-10-16). **This is the
  primary external source of the inference-layer *methods*.** Specifically
  adapted from its README/CHANGELOG (read 2026-11-16,
  `gdn2-vllm-pr/ref/deltanet_tpu/{README,CHANGELOG}.md`; its `gdn2.py` source
  was skimmed for API surface only): per-row reset semantics for decode;
  bfloat16 state storage with float32 compute; a Frobenius-norm stability cap
  on inference-time state; the prologue-fusion *idea* (activations computed
  inside the kernel from raw projections); `segment_ids`/`cu_seqlens`
  document-boundary conventions; bounded-output forward-only prefill.
  **No code was copied from deltanet-tpu** — every kernel body was written
  from scratch against our own v0.2.0 kernel architecture, our block schemes,
  our precision helpers (`atomic_gdn2/precision.py`) and our domain contracts
  (`g_max`, sigmoid gates). Their Apache-2.0 license therefore does not
  constrain our MIT code; credit is given here as the method source.
- **NVlabs/GatedDeltaNet-2** (official training-code release, May 2026):
  architecture reference; its `lit_gpt` layer's docstring was the source of
  the matrix recurrence form quoted in §2. Used earlier for the bit-exact
  checkpoint conversion (not part of v0.3.0 changes).
- **flash-linear-attention (FLA)**, MIT (Songlin Yang, Yu Zhang, Zhiyuan Li;
  contributors): the lineage of the chunked WY representation our training
  kernels implement (v0.2.0, prior attestation); its per-token `naive`
  reference style is the pattern our serial oracle follows conceptually.
  Not copied in v0.3.0.

## 4. Honest limitations
- Document resets are honored at **chunk granularity**; a chunk spanning two
  documents must be split by the caller (the serving layer owns scheduling).
- The inference kernels are validated against the serial reference and on
  TPU at the tested shapes (bt ∈ {16,32,64}, D ∈ {16,32,64,128}); the
  production shape bt=128/D=128 is validated for the *training* path
  (v0.2.0 attestation) but the *inference* kernels were not yet run at
  bt=128 on TPU.
- Decode throughput (~29 tok/s per step) is dispatch-bound (per-call Pallas
  launch from a Python loop); a `lax.scan`/jit-batched token loop is the
  identified follow-up. bf16 compute config for prefill/decode is future work.
- The backward comparison harness vs deltanet-tpu
  (`benchmarks/bench_bwd_deltanet_tpu.py`) exists but its TPU numbers are not
  part of this release (the upstream-contribution track was cancelled by the
  author on 2026-11-16; deltanet-tpu is credited as the methods source).
